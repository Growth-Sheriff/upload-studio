# Independent deployment

A public review deployment now exists at https://auto-gang-sheet.actualscope.com on the new droplet607746803 (143.198.12.234). It is not App Store approved. `deploy/public/Dockerfile` and `compose.yml` are separate from the tenant infrastructure and never call its scripts. Run them only on this newly provisioned public host, not either existing droplet. Its managed PostgreSQL, Valkey DB0, private R2 bucket, app identity and capability secrets are independent. Never reuse a tenant env or image credential bundle.

Build the public image from this worktree: `docker build -f deploy/public/Dockerfile -t auto-gang-sheet-public:<commit> .`. Apply only the public Prisma directory using `prisma migrate deploy` against the new database. No migration is intended for a live tenant database. Public image commands bypass the old entrypoint that starts every worker.

One deployment serves every shop. Web replicas share PostgreSQL sessions and Redis; image workers run in separate bounded containers. Each image worker has concurrency one, a 4 GiB cgroup, 3 GiB subprocess address-space limit, bounded temporary storage, PID cap, no privileged capabilities and per-job timeout. Add worker replicas for aggregate capacity, not per shop. Distributed shop leases cap active image jobs per shop at two across the pool. Delay congested shops to allow other shops through. Monitor delayed age, budget failures, RSS and privacy/billing retry queues.

Cloud resources must be newly created under the public project. Managed PostgreSQL and Redis are required; configure TLS, a 30-second PostgreSQL `statement_timeout` on the dedicated application role, and backups with a documented 30-day expiry. New ingress must terminate TLS on the new host and must not edit either existing Caddyfile. Apply an R2 lifecycle rule to abort incomplete multipart uploads after one day. Do not make customer files into a browsable bucket listing.

`r2-cors.json` allows non-credentialed GET/HEAD/PUT from any storefront origin. A fixed list of demo origins would break self-service installation for the next merchant; there are thousands of custom domains. CORS is not storage authorization: issuance still requires the signed installed-shop proxy and every write URL binds one owner, key, byte size and expiry. Bucket credentials and list permissions are never issued to browsers. Do not enable credentialed wildcard requests or expose an unsigned write endpoint. Verify actual R2 response headers and conditional signed PUTs in the independent demo before launch.

Hosted images remain pinned by digest; see prepare-runtime.ps1 for the currently selected image, ci.md for newer build evidence and verification.md for distinctions between built and actually deployed revisions.

The deployment uses nonroot/read-only app containers and one image process reaper. New encrypted-volume mounts cover /opt/agsu-public, Docker/containerd data, Caddy and logs with explicit service mount dependencies. Journald is volatile and Docker logs are bounded. This reduces current at-rest exposure; it does not prove secure sanitization of historical root-disk blocks. See provisioning.md and the open credential-rotation item.
